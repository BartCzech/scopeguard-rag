# Test Plan: Scope Enforcement v2.4

**Owner:** David (QA Lead)
**Environment:** Staging / Production
**Last Updated:** November 5, 2024

### Overview
This test plan covers the core retrieval validation logic for ScopeGuard's upcoming v2.4 release. All manual tests here must be automated in the Cypress E2E suite by the end of Q4.

### Test Suite: Access Control

**1. Exact Match Enforcement**
* **Setup:** User assigned `docs:hr:public`
* **Action:** Query for "employee handbook."
* **Expected:** 200 OK. Pinecone returns chunks tagged with `docs:hr:public`.

**2. Scope Inheritance (Nested Perms)**
* **Setup:** User assigned `docs:engineering:*`
* **Action:** Query for "v2 api endpoints."
* **Expected:** 200 OK. Database successfully resolves wildcard and returns chunks tagged with `docs:engineering:api:v2`.

**3. Explicit Deny Precedence**
* **Setup:** User assigned `docs:internal:*` but has an explicit deny on `docs:internal:board_minutes`.
* **Action:** Query for "Q3 runway."
* **Expected:** 200 OK, but chunks tagged with `docs:internal:board_minutes` are silently dropped from the retrieval payload. 

**4. Token Expiration (Regression Test)**
* **Setup:** Generate JWT with a 1-minute expiration. Wait 61 seconds.
* **Action:** Submit retrieval query.
* **Expected:** 401 Unauthorized. Verify the system does *not* throw a 500 error exactly on the expiration second (Fixes Staging bug reported on Nov 5).

**5. Cache Invalidation**
* **Setup:** Change user scope in Mock Okta IdP from `admin` to `guest`.
* **Action:** Submit query immediately.
* **Expected:** ScopeGuard's Redis cache must reflect the downgrade within 500ms. Admin docs should not be retrievable.
