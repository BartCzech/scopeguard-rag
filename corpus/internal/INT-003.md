# Engineering Onboarding Guide

Welcome to ScopeGuard! We are stoked to have you here. This document covers the basics to get your development environment running and outlines our engineering norms. 

### 1. Dev Environment Setup
We use Docker for almost everything locally.
1.  Clone the core repo: `git clone git@github.com:scopeguard/middleware-core.git`
2.  Request your local AWS IAM credentials and development API keys from IT.
3.  Copy `.env.example` to `.env` and paste your keys. 
4.  Run `make up`. This will spin up the local PostgreSQL database (for policy storage), Redis (for caching), and the local API gateway.
5.  Run `make test` to ensure all unit tests pass. 

### 2. PR Review Norms
* **Small is better:** Keep PRs under 400 lines of code if possible. 
* **Two Approvals:** All PRs require two approvals from core team members before merging to `main`.
* **Testing:** We require 85% test coverage for new features. The CI pipeline will automatically block PRs that drop coverage.
* **Security Context:** Because we are a security company, any PR touching the `auth/` or `retrieval/` modules requires an explicit review from Paul Kepovitz or a senior security engineer. 

### 3. Deployment Pipeline
We practice continuous deployment for our cloud environments.
* Commits to `main` auto-deploy to the Staging environment.
* Every Tuesday and Thursday at 10:00 AM PST, we cut a release branch which is automatically deployed to Production via our AWS CodePipeline. 
* Do not merge to `main` on Fridays unless it is an absolute emergency. 

If you get stuck, drop a message in `#eng-help` on Slack!
